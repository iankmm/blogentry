Title: Solving integer relation using LLL
Category: math

The infamous integer relation problem is,

**Problem.** (Integer Relation Problem) given $a_1,...,a_n\in\mathbb{R}$, finding a non-trivial solution $x_1,...,x_n\in\mathbb{Z}$ such that:
$$
a_1x_1+...+a_nx_n=0
$$

Another integer problem called the subset sum problem can be considered a subset (no pun intended) of the integer relation problem.

**Problem.** (Subset Sum Problem). Given a set $A\subset Z$ and a natural number $M$. Find a subset $S$ of $A$ such that $\sum{S}=M$

This problem can be reconsidered such that if $A=\{a_1,...,a_n\}$ then the set $S=\{a_i|x_i=1\}$ where:
$$
a_1x_1+...+a_nx_n-M=0
$$

Hence, SSP has a stronger definition than IRP.

Now, lattice is a way of looking at these problems geometrically.

**Def.** (Lattice). Given the basis $B=\{b_1,...,b_n\}$, lattice $\mathcal{L}(B)$ is defined as:
$$
\mathcal{L}=\{\sum_i{a_ib_i}|a_i\in\mathbb{Z}\}
$$

## Lattice Problems and Integer Problems

Two classic problems on lattices are:

- **SVP** (Shortest Vector Problem): Find the shortest nonzero vector $\lambda_1$ in $\mathcal{L}$.
- **CVP** (Closest Vector Problem): Given a vector $w\in\mathbb{R}^n$, find the vector $v\in\mathcal{L}$ closest to $w$.

Both problems are NP-Hard in general. However, under special conditions SVP can be solved efficiently. Our strategy is: convert the Integer Problem into SVP, then solve SVP. (CVP is not covered in this post.)

Consider the Integer Relation Problem. Since the equation is linear, we can scale the $a_i$ freely, so we may assume the integer solutions $x_i$ are much smaller than the $a_i$. Now consider the lattice generated by the rows of the following matrix:

$$
L=\begin{bmatrix}1&0&\cdots&0&a_1\\0&1&\cdots&0&a_2\\&&\ddots&&\vdots\\0&0&\cdots&1&a_n\end{bmatrix}
$$

Denoting each row as $b_i$, the vector

$$
v=x_1b_1+\cdots+x_nb_n=(x_1,\ldots,x_n,\;a_1x_1+\cdots+a_nx_n)\approx(x_1,\ldots,x_n,0)
$$

lives in $\mathcal{L}$. Since each $x_i$ is small, $v$ is a short lattice vector. So if we can solve SVP on $\mathcal{L}$, we can likely solve the Integer Relation Problem. This might sound like snake oil, but we will prove that it actually works and even show that certain instances of the NP-Complete Subset Sum Problem can be solved in polynomial time.

## Lattice Reduction

The most intuitive approach to SVP is to exploit orthogonality of the basis.

**Claim.** If the basis $B$ is orthogonal, then $\lambda_1=\min\|b_i\|$.

*pf.* Write $\lambda_1=\sum a_ib_i$ where WLOG every $a_i\neq 0$. Then:

$$
\|\lambda_1\|^2=\|a_1b_1+\cdots+a_kb_k\|^2=a_1^2\|b_1\|^2+\cdots+a_k^2\|b_k\|^2\geq a_i^2\min\|b_i\|^2\geq\min\|b_i\|^2
$$

Even if the basis is only *approximately* orthogonal, the claim still roughly holds. So if we can find a nearly-orthogonal basis for the lattice, we can solve SVP. This is the **Lattice Reduction** problem, studied since the time of Gauss. (Gauss himself gave the first solution for the 2-dimensional case.)

We already know how to orthogonalize a basis efficiently in a general vector space: **Gram-Schmidt Orthogonalization**.

**Def.** (Gram-Schmidt Orthogonalization.) Given a basis $B$ of a vector space $V$, we obtain an orthogonal basis $B^*$ via:

$$
b_i^*=b_i-\sum_{j=1}^{i-1}\mu_{i,j}b_j^*
$$

where the Gram-Schmidt coefficients are $\mu_{i,j}=\frac{\langle b_i,b_j^*\rangle}{\|b_j\|^2}$.

Of course, we can't directly use Gram-Schmidt on a lattice since the resulting basis has no reason to span the original (discrete) lattice. But what if we *approximate* Gram-Schmidt? This is exactly the idea behind the LLL Algorithm.

## LLL Algorithm

The LLL (Lenstra–Lenstra–Lovász) Algorithm was devised in 1982 by Arjen Lenstra, Hendrik Lenstra, and László Lovász.

**Def.** (LLL-Reduced Basis.) Let $B$ be a basis of $\mathcal{L}$ and $B^*$ its Gram-Schmidt orthogonalization (note $B^*\subset\mathbb{R}^n$). $B$ is called an **LLL-Reduced Basis** if:

1. **(Size Condition.)** $|\mu_{i,j}|=\left|\frac{\langle b_i,b_j^*\rangle}{\|b_j\|^2}\right|\leq\frac{1}{2}$
2. **(Lovász Condition.)** $\|b_{i+1}^*+\mu_{i+1,i}b_i^*\|^2\geq\frac{3}{4}\|b_i^*\|^2$

The $3/4$ in the Lovász Condition can be replaced by any $\frac{1}{4}<\delta<1$.

The Size Condition is easy to understand: it is equivalent to using $\lceil\mu\rfloor$ (rounding to the nearest integer) instead of $\mu$ in Gram-Schmidt.

The Lovász Condition is trickier. Two ways to think about it:

**Approach 1 (by counterexample).** Suppose only the Size Condition holds. If $b_i$ is much longer than $b_j$, $|\mu_{i,j}|$ can be less than $1/2$ regardless of the angle between them, making $\|b_i^*\|$ and $\|b_j^*\|$ wildly different in length. But with the Lovász Condition:

$$
\|b_{i+1}^*+\mu_{i+1,i}b_i^*\|^2=\|b_{i+1}^*\|^2+\mu_{i+1,i}^2\|b_i^*\|^2\geq\frac{3}{4}\|b_i^*\|^2
$$

$$
\implies\|b_{i+1}^*\|^2\geq\left(\frac{3}{4}-\mu_{i+1,i}^2\right)\|b_i^*\|^2\geq\frac{1}{2}\|b_i^*\|^2
$$

So $b_{i+1}^*$ cannot be much shorter than $b_i^*$. The condition enforces an ordering on the orthogonal vectors.

**Approach 2 (projection perspective).** Gram-Schmidt projects $b_i$ onto $\text{span}(b_1,\ldots,b_{i-1})^\perp$. In this view, the Lovász Condition says the projection of $b_{i+1}$ onto $\text{span}(b_1,\ldots,b_{i-1})^\perp$ should not be much shorter than the projection of $b_i$, again enforcing an ordering. If $\delta=1$, the ordering becomes strict.

### The Algorithm

**Def.** (LLL Algorithm.) The following algorithm transforms any basis $B$ into an LLL-Reduced Basis:

1. Approximate Gram-Schmidt Orthogonalization (using $\lceil\mu_{i,j}\rfloor$ instead of $\mu_{i,j}$).
2. Check the Lovász Condition for all $i$:
   - If satisfied for all $i$: **terminate**.
   - If $b_i^*$ and $b_{i+1}^*$ violate the condition: **swap** $b_i$ and $b_{i+1}$, then go back to step 1.

Correctness is nearly obvious: Step 1 enforces the Size Condition and Step 2 enforces the Lovász Condition. The surprising fact is that this terminates in polynomial time.

### Runtime

**Theorem.** (Runtime of LLL.) LLL terminates in polynomial time.

*pf.* Define the following quantities:

$$
d_l=\prod_{i=1}^{l}\|b_i^*\|^2,\qquad D=\prod_{l=1}^{n}d_l=\|b_1^*\|^{2n}\cdots\|b_n^*\|^2
$$

**Lemma 1.** $D$ is bounded. In particular, $D\in\mathbb{Z}^+$.

*pf.* The upper bound is trivial. Substitute the longest basis vector $b_{\max}^*$:

$$
D\leq\|b_{\max}^*\|^{2n}\cdots\|b_{\max}^*\|^2=\|b_{\max}^*\|^{n(n+1)}
$$

For the lower bound, observe that $d_l=(\det B_l^*)^2$ where $B_l^*$ is $B^*$ restricted to $l$ dimensions. By the definition of Gram-Schmidt, the transition matrix between $B_l$ and $B_l^*$ is:

$$
B_l=\begin{bmatrix}1&0\\\mu&1\end{bmatrix}B_l^*
$$

So $\det B_l^*=\det B_l\in\mathbb{Z}$, hence $d_l\in\mathbb{Z}^+$ and $D\in\mathbb{Z}^+$. The lower bound $D\geq 1$ follows.

**Lemma 2.** $D$ strictly decreases at every swap.

*pf.* Step 1 does not change $B^*$ (easy to verify). In Step 2, suppose we swap $b_i$ and $b_{i+1}$ because the Lovász Condition fails:

$$
\|b_{i+1}^*+\mu_{i+1,i}b_i^*\|^2<\frac{3}{4}\|b_i^*\|^2
$$

Let $\tilde{b}$ denote the vectors after the swap ($\tilde{b}_i=b_{i+1}$, $\tilde{b}_{i+1}=b_i$). For $l<i$: $\tilde{d}_l=d_l$ since those basis vectors are unchanged. For $l\geq i+1$: $\tilde{d}_l=d_l$ since both $d_l$ and $\tilde{d}_l$ involve the same set $\{b_1,\ldots,b_i,b_{i+1}\}$. Therefore:

$$
\frac{\tilde{d}_i}{d_i}=\frac{\|\tilde{b}_i^*\|^2}{\|b_i^*\|^2}
$$

By definition:

$$
\|\tilde{b}_i^*\|^2=\|b_{i+1}^*+\mu_{i+1,i}b_i^*\|^2<\frac{3}{4}\|b_i^*\|^2
$$

So $D$ decreases by a factor of at least $3/4$ at every swap.

By Lemma 1 and Lemma 2, the number of swaps is at most $\log_{3/4}\|b_{\max}^*\|^{n(n+1)}=O(n^2\log\|b_{\max}\|)$. Each step also runs in polynomial time, so the entire LLL Algorithm runs in polynomial time. (The precise complexity is known to be $O(d^5n\log^3\|b_{\max}\|)$.)

Note why $\delta<1$ is required: if $\delta=1$, the Lovász Condition is stricter (better output), but our proof that $D$ decreases breaks down, so polynomial termination is no longer guaranteed. Whether LLL terminates in polynomial time when $\delta=1$ is still an **open problem**.

### Approximation Guarantee

**Theorem.** Let $B$ be an LLL-Reduced Basis of $\mathcal{L}$. Then:

$$
\lambda_1\leq\sqrt{2}^{\,n-1}\|b_1\|
$$

That is, LLL solves SVP up to a factor of $\sqrt{2}^{\,n-1}$.

*pf.* First we prove a helper lemma.

**Lemma.** $\lambda_1\geq\|b_{\min}^*\|$

*pf.* Write $\lambda_1=\sum a_ib_i$ with WLOG $a_i\neq 0$ for all $i$. Expanding via Gram-Schmidt ($\mu_{i,i}=1$):

$$
\lambda_1^2=\left\|\sum a_ib_i\right\|^2=\left\|\sum a_i\sum\mu_{i,j}b_i^*\right\|^2=\|a_1b_1^*+a_2(b_2^*+\mu_{2,1}b_1^*)+\cdots\|^2\geq a_n^2\|b_n^*\|^2\geq\|b_{\min}^*\|^2
$$

Now let $b_{\min}^*=b_m^*$. From the Lovász Condition we derived $\|b_1^*\|^2\leq 2\|b_2^*\|^2\leq\cdots\leq 2^{k-1}\|b_k^*\|^2$. Therefore:

$$
\|b_1\|^2=\|b_1^*\|^2\leq 2^{m-1}\|b_m^*\|^2\leq 2^{n-1}\lambda_1^2
$$

Taking square roots gives the result. $\square$

## Solving Integer Problems using Lattices

To summarize the general approach:

1. Extract a small, linear solution from the problem.
2. Construct a lattice where that small solution becomes the answer to SVP. (A good heuristic: the target vector's norm should be around $\sqrt{n}(\det\mathcal{L})^{1/n}$ or smaller.)
3. Run LLL to solve SVP.
4. Profit.

## Subset Sum Problem using LLL

As mentioned above, certain Subset Sum instances can be solved in polynomial time, specifically when $a_i=O(2^{2n})$, i.e. the values are large relative to the number of elements. This is the **LO-Attack** (later improved to $O(2^n)$ density by the CJLOSS algorithm).

Let's work through an example with $n=5$:

```
arr = [1562, 1283, 1381, 1272, 1540]
target = 4483
```

**Step 1.** The small linear solution is given directly: solve $a_1x_1+\cdots+a_nx_n-M=0$ with $x_i\in\{0,1\}$.

**Step 2.** Construct the lattice:

$$
L=\begin{bmatrix}1&0&\cdots&0&-a_1\\0&1&\cdots&0&-a_2\\&&\ddots&&\vdots\\0&0&\cdots&1&-a_n\\0&0&\cdots&0&M\end{bmatrix}
$$

Each row is $b_i$. Then $x_1b_1+\cdots+x_nb_n=(x_1,\ldots,x_n,\;M-\sum x_ia_i)=(x_1,\ldots,x_n,0)$ is a short vector in $\mathcal{L}$.

In SageMath:

```python
L = []
N = len(arr)

for i, a in enumerate(arr):
    row = [0] * (N+1)
    row[i] = 1
    row[-1] = -a
    L.append(row)
L.append([0] * N + [target])

L = Matrix(L)
print(L)
# [    1     0     0     0     0 -1562]
# [    0     1     0     0     0 -1283]
# [    0     0     1     0     0 -1381]
# [    0     0     0     1     0 -1272]
# [    0     0     0     0     1 -1540]
# [    0     0     0     0     0  4483]
```

**Step 3.** Run LLL:

```python
L = L.LLL()
print(L)
# [ 1  0  1  0  1  0]
# [-1  2  0 -2  1  0]
# [-3 -1  2 -1  0 -4]
# [ 2 -2 -2 -3  1 -3]
# [ 1  1 -4  2  3 -2]
# [-4 -2  1  1  4  1]
```

The first row `L[0]` is exactly what we want: the last entry is 0, and the remaining entries are 0 or 1. So the solution is $x_1=1, x_2=0, x_3=1, x_4=0, x_5=1$.

```python
sol = []
for i, x in enumerate(L[0]):
    if x == 1:
        sol.append(arr[i])

print(sol)     # [1562, 1381, 1540]
print(sum(sol), target)  # 4483 4483
```

$S=\{1562, 1381, 1540\}$ and $1562+1381+1540=4483=M$. $\square$
